- withDragAndDrop(Calendar) with dateFnsLocalizer.

- Week view: no resources, with the selected tech's events only.

States:
- A loading state.
- An error state that shows the API error.
- An empty state when there are no techs: 'No active admins or techs'.

<task type="auto">
  <name>Task 2: Drag, resize, reassign, Undo, booking and edit dialogs</name>
  <files>frontend/src/pages/Dispatch.tsx, frontend/src/scheduling/BookingDialog.tsx, frontend/src/scheduling/EditDialog.tsx</files>
  <action>
Editing is enabled only with schedule:write. Otherwise set draggableAccessor and resizableAccessor to () => false, selectable to false, and hide the booking buttons.

onEventDrop and onEventResize:
- Build the body with dropPatch(appointment, {start, end, resourceId}, zone). Return if it is null.
- Mutation with an optimistic update: setQueryData moves the event, onError restores the snapshot and shows the API detail in an alert region (role='alert'), and onSettled invalidates the appointments and availability keys.
- Week view drops keep the selected tech.
- On success, show a toast (role='status', aria-live polite) with moveSummary(...) plus the server conflicts' labels when there are any, for example 'Moved to Sam · Overlaps another appointment'.
- The toast has an 'Undo' button that sends undoPatch(before, after) as a PATCH and is visible for 8 seconds.

BookingDialog.tsx (exported):
- props {open, onClose, initial?: {techId?, start?, end?, ticketId?}, zone}.
- Fields:
  - Ticket: a search box that queries the existing ticket list endpoint with q= (reuse what Tickets.tsx uses) and shows '#number subject (org)'. When initial.ticketId is set, the ticket is fixed and this field is hidden.
  - Tech: a select from listStaff.
  - Date, Start and End: date and time inputs in the board zone, converted with fromBoardDate.
  - Notes.
  - 'Visible to client', checked by default.
- Submit sends createAppointment.
- On 201 it closes, invalidates the queries and shows a toast with the conflict labels from the response.
- On a 4xx it shows the detail inline.
- Every input has a label.
- Esc closes the dialog, and focus moves to the first field when it opens.

Opening the BookingDialog:
- Selecting an empty slot (onSelectSlot, selectable when the user can write) opens it prefilled with the slot's tech (resourceId in day view, the selected tech in week view), start and end.
- 'New booking' opens it empty.

EditDialog.tsx:
- Opens on onSelectEvent (click or Enter on a focused event; RBC events are buttons).
- Shows ticket '#number subject' as a link to /tickets/{ticket_id}, the conflicts as a text list, and the fields tech, date, start, end and notes.
- 'Save' sends PATCH with only the changed fields and gets the same Undo toast.
- 'Cancel appointment' takes an optional reason, sends POST cancel and asks for confirmation first.
- Read-only users see the same dialog with the fields disabled and no Save or Cancel buttons.
- Labels: 'Tech', 'Date', 'Start', 'End', 'Notes'.
- Button names: 'Save', 'Cancel appointment', 'Close'.
- These exact names are used by the 03-03 Playwright specs.
