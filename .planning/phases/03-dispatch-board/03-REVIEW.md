## Deferred (Medium Confidence)
- `backend/app/scheduling.py` [major, 65%]: `list_appointments(with_conflicts=True)` returns up to 2000 rows. For each row, `appointment_view` runs `get(Organization)`, `get(Ticket)` and `get_user`. `conflicts_for` then adds `get_user`, `get_settings_row`, `_rows`, a holidays query, time-off and appointment queries. That is roughly 8 to 10 queries per appointment. Both Dispatch.tsx (lines 165-175) and the `onSettled` refresh (line 194) trigger this call. The refresh runs after every drag, resize and undo.
- `backend/app/scheduling.py` [minor, 50%]: `_tz` calls `ZoneInfo(user.timezone or settings.timezone)` with no guard. `put_schedule` validates the user zone, but the org `settings.timezone` is not validated here. `conflicts_for` also dereferences `tech` without a None check, because `repo.get_user` can return None.
- `backend/app/scheduling.py` [minor, 50%]: `update_appointment` does not re-check the ticket state. `create_appointment` rejects closed tickets, but a PATCH can still move or reassign an appointment on a closed ticket. It also does not re-check that the ticket still has an organization.
- `frontend/src/pages/TicketAppointmentsCard.tsx` [minor, 70%]: The card runs up to 10 extra `GET /appointments/{id}` requests, one per upcoming row, only to learn whether each row has conflicts. The list endpoint can't return conflicts for a ticket-scoped query without a range of 8 days or less.
- `frontend/src/scheduling/dispatch.css` [major, 70%]: `.dispatch-board` has `overflow: hidden` and no horizontal scroll or minimum column width. There is no `@media` rule anywhere in the file. In day view, one column per tech is squeezed into the viewport width. On a phone or tablet with several techs, columns shrink and the extra columns are clipped. Dragging also needs a mouse: react-big-calendar's DnD has no touch support, so on touch devices the only way to reassign is the Edit dialog.
- `frontend/src/pages/Dispatch.tsx` [minor, 60%]: The Day/Week toggle buttons, the Today/Prev/Next buttons, and the date and tech inputs use `py-1.5 text-sm`, which gives a height of about 32px. In `BookingDialog.tsx` line 197, the ticket result buttons use `py-1.5` and are about 28px high.
- `frontend/src/pages/Dispatch.tsx` [minor, 60%]: The toast, which holds the only Undo control, is removed after 8 seconds regardless of focus or hover. A keyboard or screen-reader user who tabs to Undo can lose it mid-interaction.
- `frontend/src/pages/Dispatch.tsx` [minor, 65%]: If the org timezone query fails, `zone` stays undefined and the board shows "Loading…" forever beside the error message. If the schedule and availability fallbacks are still pending in week view, there is the same indefinite spinner. The `Loading…` text has no `role="status"`.
- `frontend/src/scheduling/BookingDialog.tsx` [advisory, 50%]: `Modal` and `SlotInputs` are exported from `BookingDialog.tsx` and imported by `EditDialog.tsx`. The generic modal lives inside a feature file. It has an inline focus trap and no body scroll lock. Clicking the backdrop uses `onMouseDown`, so a text-selection drag that ends on the backdrop closes the dialog.
- `frontend/src/scheduling/BookingDialog.tsx` [minor, 70%]: Any mousedown on the backdrop closes the modal and discards the form, including after a text-selection drag that ends outside the dialog. In `EditDialog`, Save calls `onClose()` immediately, before the mutation has succeeded. If the PATCH fails, the user's edits are lost and the error appears only on the board behind.
- `frontend/src/scheduling/BookingDialog.tsx` [minor, 55%]: `SlotInputs` uses a fixed `grid-cols-3` for Date, Start and End inside a `max-w-lg` modal. A native date input at about 360px width or narrower gets cramped and truncated.
- `frontend/src/scheduling/EditDialog.tsx` [minor, 60%]: Save closes the dialog straight away, before the PATCH resolves, and closes it silently when nothing changed. A server rejection appears only as a page-level alert behind the closed dialog, and the user's edits are gone.
- `frontend/src/pages/Dispatch.tsx` [advisory, 50%]: The off-hours, time-off and pending shading is conveyed only by background colour and pattern. The conflict reasons are in a `title` tooltip, which touch and screen-reader users do not reliably get. Off-hours blocks have no text at all.
- `frontend/src/Dispatch.test.tsx` [major, 70%]: No test sends a resize through the board (`onEventResize`), and no test sends a drag/drop (`onEventDrop`) through the component. `Dispatch.test.tsx` only covers the edit dialog path. Resize is covered only by the `dropPatch` unit test in `board.test.ts`. The Playwright spec has one mouse drag but no resize. The week-view drop rule is also untested: `resourceId` is ignored in week view.
- `frontend/e2e/dispatch.spec.ts` [major, 60%]: The Playwright spec has three tests: book from the ticket then edit and undo, reassign through the edit dialog, and a vertical drag. None resizes an event. None drags an event to another tech's column, so cross-resource reassign by drag is untested. None exercises a time-off or outside-hours conflict, or starting a timer from the ticket card. Resize reaches `onMove` through `onEventResize`, but only `dropPatch` unit tests and one edit-dialog test cover it. No test checks that `resizableAccessor` or the rbc resize handles reach the PATCH.
- `backend/app/scheduling.py` [advisory, 55%]: `put_schedule` re-validates the work hours (empty list, duplicate weekdays, 0 <= start < end <= 1440). `SchedulePut` and `WorkHoursDay` already enforce this, so the service copy is unreachable through the API.
- `backend/tests/test_scheduling_api.py` [minor, 55%]: No test checks that appointments are client-scoped. The code and module docstring say queries go through `Scope` and RLS. No test shows that a scoped user cannot read or change another organisation's appointments, or that `PATCH` and cancel return 404 across organisations.
- `frontend/src/pages/TicketAppointmentsCard.tsx` [minor, 75%]: Every row repeats the same "Open on board" link and "Start timer" button, and none has a row-specific accessible name. Loading is not shown, because `list.isLoading` renders nothing. When `canBook` is false, the Book button vanishes with no explanation, for example when the ticket has no organisation or is closed. A failed timer start shows its error at the bottom of the card, away from the row.
- `frontend/src/scheduling/dispatch.css` [minor, 70%]: Conflict and pending colours are hard-coded hex values (#f59e0b, #d97706, #92400e, #b45309). They are not design tokens, although the rest of the file uses `var(--color-*, fallback)`. `Dispatch.tsx` mixes raw palette classes (`bg-blue-600`, `text-amber-800`, `bg-red-50`) with the `text-on-accent` and `bg-surface` tokens. The amber outline (#f59e0b) on white has a contrast ratio of about 2.1:1.
- `frontend/src/pages/Dispatch.tsx` [minor, 60%]: The whole calendar is swapped for a "Loading…" paragraph whenever `appts.isLoading` is true, which includes each navigation to an uncached day or week. The board unmounts and loses its scroll position (`scrollToTime` resets) and layout height, so the page jumps.
- `frontend/src/pages/Dispatch.tsx` [minor, 60%]: Off-hours shading returns `null` from `EventBlock`. It is conveyed only by a hatch pattern that is visible on screen but has no text alternative. Conflict state on an event is a ⚠ glyph and an outline, and the tooltip carries the conflict text. The tooltip is hover-only, so keyboard and touch users cannot read what the conflict is without opening the edit dialog. The Day/Week segmented buttons have no `:focus-visible` style of their own.
- `frontend/src/scheduling/api.ts` [minor, 70%]: `AppointmentListParams` declares `from` and `to` as required strings, but the backend accepts a list without them when `ticket_id` is given. The ticket card works around this with `{ ticketId: t.id } as AppointmentListParams`, a cast that hides a missing property. `listAppointments` also sends `from: undefined`, which `query()` silently drops.
- `frontend/src/pages/Dispatch.tsx` [major, 60%]: Day-view columns come only from active admins and techs (`listStaff`). The appointment list is not filtered by tech, so a scheduled appointment whose tech was deactivated or changed role has no matching resource. react-big-calendar does not render events with an unknown `resourceId`. In week view, a deactivated tech cannot be chosen, so their appointments cannot be reached at all. `EditDialog` has special handling for a tech who is no longer bookable, but the board never gives the user a way to open that dialog.
- `frontend/e2e/dispatch.spec.ts (also frontend/src/Dispatch.test.tsx)` [major, 70%]: No test exercises resize. `onEventResize` is wired to `onMove`, but the e2e spec covers only an edit-dialog move, a reassign and a one-hour drag. No test covers a PTO or outside-hours conflict (approved or pending) on the board. Nothing tests week-view drag or the timer started from an appointment end to end.
