  <action>
Extend backend/dev/fake_graph.py: an in-memory EVENTS dict keyed by (user lowercased, event id). POST /v1.0/users/{user}/events: if a stored event for that user has the same transactionId, return it with 201 (idempotent create); else store it with a new uuid id and return 201 with the event plus id. PATCH /v1.0/users/{user}/events/{id}: 404 if missing, else merge and return 200. DELETE same path: 404 if missing, else remove and return 204. POST /v1.0/users/{user}/calendar/getSchedule: return value[] with one entry per requested schedule whose scheduleItems are that user's stored events overlapping the window (status from showAs) plus any blocks injected by a control endpoint. Control endpoints: POST /_busy {"user", "start", "end", "status"} adds an injected busy block; GET /_events returns all stored events; POST /_fail {"path_contains", "status", "count"} makes the next count matching requests return that status (for trying retries locally). Update the module docstring with the new endpoints. Keep the existing mail endpoints unchanged. Use only the standard library.
