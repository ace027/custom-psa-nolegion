<task type="auto">
  <name>Task 3: Worker push job</name>
  <files>backend/app/calendar_sync.py, backend/app/worker.py, backend/tests/test_calendar_sync.py</files>
  <action>
In backend/app/calendar_sync.py add push_pending(db, client, *, now, batch=20). Return 0 without touching rows when settings.outlook_sync_enabled is false. Claim up to batch rows with state 'pending' and next_attempt_at <= now using FOR UPDATE SKIP LOCKED, ordered by next_attempt_at. For each row, load the appointment, its ticket id and the current tech's email; one row per commit. Rules: (a) appointment ended more than 1 day before now and never synced -> state 'skipped'. (b) appointment cancelled -> delete_event on synced_tech's email if graph_event_id is set, then clear graph_event_id, synced_tech_id, set synced_version = desired_version, state 'synced'. (c) tech changed (synced_tech_id set and != tech_id) -> delete from the old tech, clear the event id, generation += 1, then continue as a create. (d) no graph_event_id -> create_event(tech email, event_payload(ticket_id, starts_at, ends_at, settings.public_url), transaction_id f'psa-appt-{appointment_id}-{tech_id}-{generation}'), store the id and synced_tech_id. (e) graph_event_id set -> update_event; on GraphError status 404 clear the id, generation += 1, and create. On success: synced_version = desired_version, state 'synced', attempts 0, last_error NULL; if desired_version changed while pushing (re-read under the lock), leave state 'pending'. On GraphError: attempts += 1, last_error = str(error)[:500]; permanent (not transient) or attempts >= 6 -> state 'failed'; else next_attempt_at = now + min(2**attempts, 60) minutes. A tech without an email -> 'failed' with last_error 'Tech has no email address'. Log one INFO line per pushed row and WARNING per failure, never the token. In backend/app/worker.py add calendar_jobs(client) following billing_jobs (new_session, set_org_scope(db, 'all'), catch and log exceptions); call it every loop iteration in the mail-configured branch only (calendar sync needs the Graph credentials). Write backend/tests/test_calendar_sync.py with a FakeCalendarClient implementing create_event (idempotent on transaction_id), update_event, delete_event and failure injection, covering: disabled setting does nothing; create pushes the approved payload with the transaction id; a retried create with the same transaction id makes no duplicate; move updates the same event id; reassign deletes from the old tech and creates for the new one; cancel deletes and a second delete 404 is fine; 404 on update recreates; transient error backs off 2 minutes after the first failure and fails after 6; 403 fails at once with last_error; a write during a push leaves the row pending; ended appointments are skipped; rows of two orgs are both processed under set_org_scope('all').
