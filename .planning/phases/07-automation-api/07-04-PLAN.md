Required interfaces/content structure:

- routes (tag 'automation', require automation:manage): GET /api/automation/rules, POST /api/automation/rules (201), PATCH /api/automation/rules/{id}, POST /api/automation/rules/{id}/archive, POST /api/automation/rules/test, GET /api/automation/rules/{id}/runs?limit=
- RunOut trace: {conditions:[{field, op, value, actual, matched}], actions:[{type, params, status 'done'|'skipped'|'failed', detail}]}
Edge/error cases:
- unknown field, op not allowed for the field, wrong value type, contains on a non-subject field, empty actions list, unknown action type, assign to an inactive or nonexistent user, unknown queue/priority/endpoint, trigger outside RULE_TRIGGERS -> 409
- rmm_alert.* trigger with alert_severity condition; alert_severity condition on a ticket.* trigger -> 409
- escalate on the most urgent priority -> skipped with detail 'already most urgent'
- create_ticket on a ticket without an organization -> skipped
- notify a user with notify_assigned off or mail not configured -> skipped (notify returns False)
- archived or disabled rule never runs
- two rules both match -> both run in position order
- update_ticket by a rule action emits ticket.assigned webhooks but no rules run (depth guard)

automation.py per interfaces. facts(): organization_id, queue_id, category_id, priority_id, ticket_type_id, status, source, assignee_id, subject, alert_severity (alert.severity or None). evaluate(): AND of all conditions; ops eq/ne/in/not_in/contains(case-insensitive substring, subject only)/is_empty/is_not_empty; returns matched and per-condition trace with actual values. validate(): name 1-100 chars, trigger in events.RULE_TRIGGERS, conditions list (<= 20) of {field, op, value} checked against FIELDS (alert_severity only for rmm_alert.* triggers; ids must reference existing rows), actions list 1..10 of {type, ...params} with referenced users active, queues/priorities/endpoints existing, create_ticket subject 1-200 chars. on_event(): load enabled, non-archived rules for the trigger ordered by position, id; for each: skip if runs in the last hour >= RATE_CAP (then set enabled false, disabled_reason 'Fired more than 200 times in an hour', audit automation.rule_auto_disabled once); evaluate; insert AutomationRun(rule_id, event_id, matched, trace) inside a savepoint catching IntegrityError (already ran -> skip); when matched, set token = events.automation_depth.set(1) and run each action in ctx.db.begin_nested() catching Exception into the trace as failed (type name and str truncated to 200), finally reset the token; update fire_count/last_fired_at and the run trace; audit automation.rule_fired with detail {rule_id, event_id, ticket_id, actions statuses}. Actions: assign/set_queue/set_priority via ticket_services.update_ticket(ctx, ticket.id, {...}); escalate picks the active priority with the next lower rank than the current one, update_ticket priority_id, then ticket_services.system_note(ctx, ticket, f'Escalated by rule {name}'); notify via notifications.notify(ctx, user_id, ticket, 'rule_notify', f'rule:{rule.id}:{event_id}') (add 'rule_notify' to notifications.PREFERENCE -> 'notify_assigned' and HEADLINE -> 'matched an automation rule'); webhook via webhooks.enqueue(ctx, type, event_id, events.payload(...), endpoint_ids=[id]) (unique constraint means an already-subscribed endpoint is not sent twice: catch it in the savepoint and mark skipped); create_ticket via ticket_services.create_ticket(ctx, {organization_id, subject, queue_id?, priority_id?, description: f'Created by automation rule {name} from ticket #{n}.'}, source='rule') then ticket_links.link_related. Register on_event into events.RULE_HOOK at import time and import app.automation in events.py lazily inside emit before calling hooks (or in app.main) so the hook is always registered in the API and the worker — choose: events.emit does `from app import automation  # noqa: F401` before reading RULE_HOOK. dry_run evaluates without writing (no AutomationRun, no audit) and lists the actions that would run with resolved names. test_automation.py: evaluate truth table, each action triggered by a real service event, loop guard (an assign rule plus a rule on ticket.assigned: second never runs from the first's change, but a webhook delivery for ticket.assigned exists), idempotent re-run of on_event with the same event_id, rate cap by inserting 200 runs in the last hour, a failing action (monkeypatched to raise) leaves the ticket change committed and the run trace with 'failed', audit rows.
