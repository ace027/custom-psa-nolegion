## Deferred (Medium Confidence)
- `backend/app/renewals.py, /home/user/custom-psa-nolegion/backend/alembic/versions/0030_crm.py` [major, 70%]: Uniqueness is on (agreement_id, lead_days), and `due_on` is frozen at creation. If staff extend an agreement's `end_date` after reminders exist, for example a renewal done by editing the agreement, the old reminders block recreation for the new term. The stale reminders keep the old `due_on`. Renewals of that agreement are never reminded again, and the existing renewal opportunity keeps the old close date.
- `backend/app/crm.py` [minor, 55%]: `link_quote` locks the opportunity but not the quote. A concurrent `accept_quote` can commit between the `quote.status in OPEN` check and the link commit. `on_quote_accepted` has already scanned and does not see the new link. The opportunity then stays open, linked to an accepted quote, with no agreement.
- `backend/app/crm.py` [major, 65%]: `update_opportunity` does not check whether the opportunity is open. Amount, term, expected close date and owner of a won or lost opportunity can be edited. `move_stage` also lets a won opportunity go back to open (lines 319-347), including one already linked to an agreement through a quote acceptance. It does not clear `agreement_id` or the won state.
- `backend/app/crm.py` [minor, 65%]: `forecast` loads every opportunity row, including all closed ones, and aggregates them in Python. It also calls `calendar(ctx)` on each request.
- `frontend/src/pages/crm/Pipeline.tsx` [minor, 70%]: The lost-reason input sits inside a `<label>` with the visible text "Why was “X” lost?". It also has `aria-label="Lost reason"`, which overrides that text. The accessible name no longer contains the visible label text.
- `frontend/src/pages/crm/OpportunityPage.tsx` [minor, 75%]: Choosing a "lost" stage reveals the lost-reason form but does not move focus to it. Pipeline.tsx does (`reasonRef`, and focus returns to the select on cancel). Here the stage select keeps `value={o.stage_id}` while the form is open, so it still shows the old stage. Cancel does not restore focus. The "Say why it was lost." alert is not tied to the input with `aria-describedby` or `aria-invalid`.

NavLink does set `aria-current="page"`. The active state has no colour contrast against the other tabs. Four tabs can overflow on narrow screens.
- `backend/app/routers/crm.py` [advisory, 55%]: Patch handling is inconsistent. Leads and opportunities use `_patch` with a module-level `NOT_NULL` tuple shared across all models. Stages use `model_dump(exclude_unset=True, exclude_none=True)` inline.

There is no `role="alert"` or in-card feedback, and no loading indicator for the initial `opps` or `stages` query.
