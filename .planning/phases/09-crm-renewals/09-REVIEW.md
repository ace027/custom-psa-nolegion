## Deferred (Medium Confidence)
- `backend/app/renewals.py` [major, 65%]: `_open_renewal` only finds renewal opportunities in an open stage. When an agreement has a renewal opportunity that is already won or lost, a later lead time (for example 30 days after 90 was handled) creates a fresh reminder. Finding no open renewal opportunity, the scan then creates a second renewal opportunity for the same agreement. A won opportunity should be the case that blocks this. This happens when the quote is accepted before the 30-day mark and the old agreement keeps an `end_date >= today`: `quoting` sets it to `start - 1`, which can be in the future.
- `backend/app/crm.py` [minor, 50%]: `on_quote_accepted` raises `Conflict` from `_active_terminal` when no active won stage exists, and this runs inside `quoting.accept_quote` after the agreement is created. Acceptance of the quote then fails entirely because of CRM configuration.
- `frontend/src/pages/crm/Renewals.tsx` [major, 70%]: "Days left" is a bare number. Overdue renewals show a negative number such as `-3` with no label. Urgency (overdue, due within 30 days) has no visual or text treatment.
- `frontend/src/pages/crm/OpportunityPage.tsx` [major, 75%]: The Owner `<select>` has no option for the current owner when `users` is not loaded. That is always the case for read-only users, since the query is `enabled: write`. The first option reads "Unowned" whenever `f.owner` is set, so the owner's name is only shown when `!f.owner`.
- `frontend/src/pages/crm/Forecast.tsx` [advisory, 50%]: The row label is a `<td>`, not `<th scope="row">`. The "Total" row is distinguished only by `font-semibold`. The "Won this month" tiles show monthly amounts only, and the deal counts sit in separate small print below (lines 27-30).
- `backend/app/crm.py` [minor, 70%]: `create_opportunity` maps every `IntegrityError` to "That agreement does not belong to this client". The message assumes one specific constraint. Other violations (for example a bad `quote_id` or `owner_id` foreign key) would get the same wrong message. `_flush` rolls back the whole session on failure.
- `backend/app/crm.py` [minor, 65%]: `link_quote` imports `app.quoting.OPEN` inside the function. This hides a circular dependency, because `quoting` calls `crm.on_quote_accepted`. `renewals.py` also hard-codes `term_months: 12` instead of a named constant, and `crm.py` defines `BUCKET_MONTHS` as a constant.
- `frontend/src/pages/crm/Renewals.tsx` [major, 70%]: "Dismiss" runs immediately on click. It has no confirmation and no undo, and the row disappears after the refetch. The mutation's `isPending` disables every row's Dismiss button, not only the clicked row. Nothing confirms that the dismissal happened.
- `frontend/src/pages/crm/OpportunityPage.tsx` [minor, 60%]: While the opportunity loads, the page returns `<ErrorMsg error={null}/>`, which is a blank screen with no loading indicator. When a lost stage is chosen, the select continues to show the old stage until the reason is confirmed. Cancel does not call `move.reset()`, so a stale error can persist.
- `backend/app/routers/crm.py` [advisory, 60%]: `_lead_out(ctx, lead)` has no type annotation on `lead`. `Organization` is imported inside `_opp_out`, and `OpportunityOut` is built from `getattr` over `model_fields` guarded by `hasattr`.
- `backend/tests/test_crm_api.py (and backend/tests/test_renewals.py)` [minor, 65%]: No test covers a null `status` PATCH on a lead (Finding 1). No test covers `scan` when `first_open_stage` or `create_opportunity` fails (Finding 2). No test covers `renewals.dismiss` of a non-open reminder returning 409, or dismissing out of scope.
- `frontend/src/pages/crm/OpportunityPage.tsx` [minor, 65%]: This has the same problem as Finding 1. The lost-reason field appears after the select change with no focus move. The `bad` error is set separately from the input and has no `aria-describedby` or `aria-invalid` link. The Cancel button does not call `move.reset()` or put the select back. In Pipeline.tsx the error `<p role="alert">` has the same missing association.
- `frontend/src/pages/crm/Pipeline.tsx` [minor, 75%]: While stages and opportunities load, the board renders nothing: no loading text, skeleton or `aria-busy`.
