<task type="auto">
  <name>Task 2: Receiving, inventory and delivery billing</name>
  <files>backend/app/procurement.py, backend/tests/test_procurement.py</files>
  <action>
receive(ctx, po_id, line_id, quantity, serials): PO must be 'ordered' or 'partial' (Conflict otherwise); quantity >= 1 and received_quantity + quantity <= line.quantity (Conflict 'more than ordered'); if line.serialised: len(serials) must equal quantity and each serial must be unused (case-insensitive; Conflict naming the duplicate serial) -> one InventoryItem per serial with quantity 1; else serials must be empty -> one InventoryItem with that quantity. Items copy product_id, description, unit_cost_cents from the line, received_on = today, status 'in_stock', organization_id = the PO's organization_id (reserved for that client, or NULL for stock). Then line.received_quantity += quantity and the PO status becomes 'received' when every line is fully received, else 'partial'. Audit 'purchase_order.receive'.

deliver(ctx, item_id, organization_id, quantity, asset_id, create_asset, delivered_on): item must be 'in_stock' (Conflict otherwise); if the item is reserved for a different client -> Conflict; organization must exist and be visible. quantity defaults to item.quantity; 1 <= quantity <= item.quantity; for a partial delivery of a non-serialised item, split: reduce the original item's quantity and create a new item row (same line, product, cost, received_on) holding the delivered quantity, and deliver that row. Set status 'delivered', organization_id, delivered_on (default today). Asset: asset_id given -> it must belong to the same organization (Conflict otherwise) and the item must have a serial or quantity 1; create_asset -> create an Asset for the organization using the item description as its name and the serial number (fill required asset columns the same way routers/assets.py creation does) and link it; both given -> 422. Billing (MONEY RULE, do exactly this): billable = the source PO line's billable flag (items with no PO line are billable); if billable: markup_bp = resolve_markup(line) (for an item with no line: product rule, then category rule, then default); unit_price_cents = money.marked_up(item.unit_cost_cents, markup_bp); create ProductCharge(organization_id, product_id, ticket_id=None, description = item description plus f' (S/N {serial})' when serialised, quantity = Decimal(delivered quantity), unit_price_cents, taxable = line.taxable (or product.taxable, else True), charged_on = delivered_on, created_by = ctx.user id); store item.markup_bp and item.product_charge_id. Not billable: no charge, item.markup_bp stays NULL. Never compute invoice amounts or tax here: the billing run does that from the charge.

undo_delivery(ctx, item_id): item must be 'delivered'; if it has a charge whose invoice_line_id is not NULL -> Conflict 'Already invoiced: issue a credit memo instead'; else set charge.voided_at = now, item.product_charge_id stays for history? No: clear product_charge_id (unique column) after voiding, clear markup_bp, delivered_on, asset_id (do not delete a created asset), status back to 'in_stock', organization_id back to the PO's organization_id (or NULL). consume(ctx, item_id): in_stock -> 'consumed' (internal use, never billed). Audit every transition.

test_procurement.py: cover receiving (partial then full -> statuses; over-receive; serial count mismatch; duplicate serial across POs, case-insensitive; serials on a non-serialised line rejected), delivery (full and split partial; reserved-for-other-client rejected; asset link same-org only; create_asset makes an asset with the serial), markup resolution order (line > product rule > category rule > default; default 0 bills at cost), the exact client price e.g. cost 12,345 c at 1,500 bp -> charge unit price 14,197 c and quantity 3 for a 3-unit delivery, non-billable lines create no charge, undo before invoicing voids the charge and restores stock, undo after the charge is invoiced (run the real billing run for the org, as test_expenses/test_invoicing do) is refused, and an end-to-end test where a delivered item appears as one 'product' invoice line with amount = quantity x marked-up unit price and tax per the taxable flag.
