## Deferred (Medium Confidence)
- `backend/app/report_schedules.py` [major, 75%]: When `_send_one` fails (for example a transient DB error, or `csv_for` raising), `run_due` writes a `failed` row in `ReportScheduleRun` for that `(schedule_id, period_start)`. The `done` check on lines 221-228 matches any run row, whatever its status. The schedule is therefore never retried for that period, and the failure is permanent.
- `frontend/src/pages/reports/SlaReport.tsx` [minor, 65%]: The `useRange` date inputs fire a query and rewrite the CSV link on every keystroke or partial edit. There is no validation that from <= to. An inverted or empty range is sent to the server, and the CSV link points at it.
- `frontend/src/pages/Dashboard.tsx` [minor, 60%]: `Stat` and `Tile` are near-duplicates (the same card styling and warn styling). `Business` and `MyWeek` also each run their own 60-second `refetchInterval`, so three polls are active on the page.
- `frontend/src/pages/reports/ReportSchedules.tsx` [advisory, 50%]: The Runs, Edit and Deactivate buttons, and the form's checkboxes, use the default `Button` and bare checkbox sizing (`py-1.5`, a 16px native checkbox). Touch targets are under 44px.
- `frontend/src/pages/reports/SlaReport.tsx` [minor, 60%]: `PctBar` uses `role="img"` with `aria-label` on a `span`, and it is repeated in every row. The value is already in the adjacent text cell. The unfilled bar is `bg-slate-200` against white or surface, a contrast of about 1.2:1. The filled `bg-blue-500` is about 3.7:1 against white.
- `frontend/src/pages/Dashboard.tsx` [minor, 70%]: `Tile` links have only `hover:border-blue-400`, with no `focus-visible` style. The warning state is conveyed only by an amber background and border. The accessible name is the value followed by the label, so a screen reader hears "3 My SLA at risk".
- `frontend/src/pages/Dashboard.tsx` [minor, 50%]: The `h3` "Receivables by days past due" sits inside the Business card, which uses an `h2`. That is fine. However, the "My week" and "Business" card groups have no wrapper that gives the two tile groups a list or group semantics, and the tile grids are plain `div`s.
- `frontend/src/pages/reports/ReportSchedules.tsx` [minor, 50%]: Schedule status ("active" or "inactive") is shown only as lowercase gray text (`text-slate-500`) inside the same line as the metadata. `text-xs text-slate-500` at line 69 is small. slate-500 on white is about 4.8:1, which passes, but on `bg-slate-50` (line 90) with `text-xs` it is borderline.
- `backend/app/routers/reports.py` [minor, 70%]: `_metric_csv` gets the CSV text back from `metrics.csv_for`, then re-parses it with `csv.reader` just to count rows for `record_export`. It also records the raw `from` and `to` query values, which are `None` when the caller omits them. The range actually used is only available inside `csv_for` and is discarded.
- `backend/app/dashboards.py` [minor, 75%]: `me()` calls `metrics.utilisation` for the whole team (all users, holidays, time off, work hours, free-window computation) and then picks out the caller's row. `utilisation` has no `user_id` filter.
- `backend/app/report_metrics.py` [advisory, 55%]: `sla()` re-validates `group` against a hard-coded tuple, duplicating the `SlaGroup` Literal. `REPORTS` (line 92) is also defined separately from the `csv_for` dispatch, which hard-codes the same names again.
- `backend/app/report_schedules.py` [minor, 70%]: The subject is always `"{name}: {start} to {end}"`, built from the previous-week or previous-month period. For an `aging` schedule that period does not apply, because the report is "as of today", and the body says "As of {today}".
- `frontend/src/pages/reports/ReportSchedules.tsx` [minor, 55%]: `holdsReportRead` hardcodes the roles "admin" and "billing" instead of using the permission data. The `/users` query also needs `user:manage`, but the page is shown to anyone with `report:read`.
- `frontend/src/Dashboards.test.tsx` [minor, 60%]: The frontend tests cover only the SLA report, the empty-state and schedule-form gate, and the dashboards. They do not cover `AgingReport`, `UtilisationReport`, `ProfitabilityReport`, the schedule create/edit/toggle flows, the Runs table, or the negative-margin display path.
- `backend/tests/test_report_schedules.py` [advisory, 50%]: There is no test for the concurrent-worker path in `run_due`: the `IntegrityError` swallow when another worker records the period, or the `skip_locked` locking.
- `frontend/src/pages/reports/ReportSchedules.tsx` [minor, 65%]: The Runs toggle button has no `aria-expanded` or `aria-controls`. The `aria-label` "Runs for X" replaces the visible "Runs" text, which is acceptable for 2.5.3 only because it contains the visible word. Newly shown content isn't announced. The Runs table headers have no `scope` or caption. Run status is plain text (`r.status`) with no visual differentiation of failed runs.
- `frontend/src/pages/reports/ReportSchedules.tsx` [minor, 55%]: The form fields (Name, Report, Frequency) have no required indication beyond the native `required`. `maxLength` gives no visible counter. After a successful save or cancel, focus is lost because the form unmounts. The fixed 1-28 day limit isn't explained, and the placement of "Active" below the fieldset is inconsistent with the other grouped controls.
- `frontend/src/pages/reports/ReportSchedules.tsx` [advisory, 50%]: "Deactivate" applies immediately with no confirmation, and nothing indicates a success. The user-facing copy uses the raw permission string "report:read".
- `frontend/src/pages/reports/SlaReport.tsx` [minor, 60%]: Design system adherence. The report pages hardcode the heading class `text-2xl font-bold tracking-tight` and `text-blue-700 hover:underline` link styles instead of using shared tokens. `dl`, `num`, `useRange`, `PctBar` and `inputCls` are exported from a page module (`SlaReport`) and imported by sibling pages. The CSV download is a bare `<a>` styled as text, not a `Button`-styled link, and it has no `download` attribute or file-type hint.
- `frontend/src/pages/reports/UtilisationReport.tsx` [minor, 50%]: The label "Utilisation (n)" and the note "n is capacity" are cryptic. The percentage cells use `pctN(bp, capacity_minutes)`, but the output format for a zero-capacity case isn't explained in the UI. Billable % is also not given a bar, unlike Utilisation.
- `backend/app/report_schedules.py` [minor, 55%]: `update_schedule` lets `report`, `frequency`, `weekday` and `day_of_month` change at any time. Idempotency is keyed only on `(schedule_id, period_start)`, so the run key ignores which report the run was for. If a schedule is edited after a run exists for the current period (for example `sla` changed to `profitability`, or `weekday` moved), the changed schedule is silently skipped for that period. Weekly and monthly periods also have different `period_start` values, so switching frequency can send a second email in the same cycle.
- `frontend/src/pages/reports/SlaReport.tsx` [minor, 55%]: The date inputs are not validated. The same applies to the `colSpan` values in Aging (9), Profitability (10) and Utilisation (7).
