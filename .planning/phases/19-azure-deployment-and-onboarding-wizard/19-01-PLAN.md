  <name>Task 1: main.bicep</name>
  <files>deploy/azure/main.bicep, deploy/azure/main.parameters.example.json</files>

Bicep for: Log Analytics workspace; VNet with subnets for Container Apps and PostgreSQL (delegated); PostgreSQL Flexible Server v16, private access, private DNS zone, admin password from a Key Vault secret reference parameter (@secure, no default), database 'psa'; storage account (TLS1.2, no public blob access) with an Azure Files share 'attachments' mounted into the Container Apps environment; Azure Container Registry (admin user disabled, AcrPull for the identity); Key Vault (enableRbacAuthorization true, purge protection, soft delete 90); one user-assigned identity with Key Vault Secrets User and Key Vault Secrets Officer on that vault and AcrPull; Container Apps environment; container apps 'api' (internal ingress 8000, uvicorn), 'worker' (no ingress, python -m app.worker), 'proxy' (external ingress 443 via the frontend image, Caddy upstream api) and a Container Apps Job 'migrate' (alembic upgrade head, then python -m app.bootstrap_admin when BOOTSTRAP_ADMIN_EMAIL is set; the module is built in plan 19-02). Every secret env var (DATABASE_URL, MIGRATION_DATABASE_URL, SESSION_SECRET, CREDENTIALS_KEY, ENTRA_CLIENT_SECRET, PORTAL_ENTRA_CLIENT_ID, PORTAL_ENTRA_CLIENT_SECRET, GRAPH_TENANT_ID, GRAPH_CLIENT_ID, GRAPH_CLIENT_SECRET, MAIL_MAILBOX) is a Container Apps secret with keyVaultUrl + identity; non-secret env (PUBLIC_URL, ENTRA_TENANT_ID, ENTRA_CLIENT_ID, ATTACHMENTS_DIR=/data/attachments, ONBOARDING_ENABLED=true, KEY_VAULT_URL, AZURE_CLIENT_ID of the identity, ENVIRONMENT=production) are plain env. api and worker mount the share read-write (uploads go through api). Outputs: proxy FQDN, vault name, identity client id. Parameter example file with placeholders only.

<task type="auto">
  <name>Task 2: deploy.sh</name>
  <files>deploy/azure/deploy.sh</files>
  <action>
Idempotent bash (set -euo pipefail) taking env vars RESOURCE_GROUP, LOCATION, NAME_PREFIX, PUBLIC_HOST, BOOTSTRAP_ADMIN_EMAIL: az login check; create the resource group; create the Key Vault first (small bicep module or az keyvault create with RBAC) and grant the signed-in operator Key Vault Secrets Officer; generate session-secret (openssl rand -base64 48), credentials-key (python3 -c Fernet-format: urlsafe base64 of 32 random bytes) and the PostgreSQL admin and app passwords, and az keyvault secret set them only if absent, passing values via --file from a mktemp file with umask 077 that is shredded/removed in a trap, never on the command line or stdout; pre-create portal-entra-client-id, portal-entra-client-secret, graph-tenant-id, graph-client-id, graph-client-secret, mail-mailbox with value 'unset' if absent; create or reuse the staff SSO app (az ad app create --sign-in-audience AzureADMyOrg --web-redirect-uris https://$PUBLIC_HOST/api/v1/auth/callback, required resource access Microsoft Graph delegated openid, profile, email, User.Read only; az ad sp create; az ad app credential reset with --years 1 output captured into the vault as entra-client-secret without echo); build and push images with az acr build; az deployment group create with main.bicep; start the migrate job and wait; print only the URL, vault name and next step ('sign in as $BOOTSTRAP_ADMIN_EMAIL and open Setup'). Never print or log secret values (no set -x).
